# 08 · 技术选型与项目架构（本项目）

## 1. 技术选型定案

| 层 | 选型 | 理由 |
| :--- | :--- | :--- |
| 渲染 | **Phaser 4 + TypeScript**（2D 等轴精灵） | Townsmen 式 2.5D 的本质是等轴 2D 精灵排布；Phaser 自带精灵/瓦片/动画/输入/相机，包体积小，性能足够支撑上千实体 |
| 构建 | **Vite + vite-plugin-pwa** | Service Worker 自动缓存全部资源 → 断网可玩；manifest 支持添加桌面 |
| 存档 | **IndexedDB + Dexie.js** | 见 07 文档 |
| 逻辑架构 | 固定时间步进 + 轻量组件化 | 模拟逻辑与渲染帧率解耦；存档=纯数据快照 |
| 寻路 | 网格 A*（手写或 pathfinding.js） | 居民通勤 |
| 美术起步 | Kenney.nl 等轴资源包 / Blender 渲 2D 序列帧 | 独立开发最低成本路径 |

### 等轴投影核心公式

```
screenX = (tileX - tileY) * TILE_W / 2
screenY = (tileX + tileY) * TILE_H / 2
渲染顺序: 按 (tileX + tileY) 升序（画家算法保证遮挡正确）
```

## 2. 主循环架构

```
requestAnimationFrame
  └─ 累积真实时间 delta
       └─ while (acc >= TICK_MS):        // 固定步进, TICK_MS = 100
            SimWorld.tick()               // 生产/消耗/税收/AI/灾害
       └─ RenderSystem.render(alpha)      // 插值渲染, 与逻辑解耦
       └─ SaveSystem.maybeAutosave()      // 30s 脏检查
```

**关键纪律**：`SimWorld` 不 import 任何 Phaser 对象，只操作纯数据——这是存档、离线结算、未来单元测试的共同前提。

## 4. 里程碑规划

| 里程碑 | 交付物 | 验收标准 |
| :--- | :--- | :--- |
| **M1 地基** | Vite+PWA 脚手架、等轴网格渲染、点击建建筑、Dexie 存档/读档 | 断网刷新后世界状态完整恢复 |
| **M2 经济闭环** | 渔屋/农田/磨坊/面包房生产链、仓库容量、订单板 | 种-收-加工-交订单全流程可玩 |
| **M3 居民** | 民居/移民/需求/幸福度/税收档位、通勤寻路动画 | 提税降幸福、断粮人走的因果可观察 |
| **M4 纵深** | 商队运输、季节、离线结算报告、灾害三件套（火灾/瘟疫/强盗） | 离线 8h 上线收到结算报告；火灾可被消防塔扑灭 |
| **M5 长线** | 声望科技、成就树、动物园/矿场扩展区、数值平衡 | 完整 5 小时游玩曲线无死锁 |

## 5. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 数值失衡（玩家 1 小时就财务自由） | 数值全部放 `src/sim/data/` 静态表；M2 起每周跑一次无头模拟脚本校验经济曲线 |
| 精灵美术工作量大 | 先用 Kenney 免费等轴包 + 纯色块，玩法验证后再换皮 |
| IndexedDB 写坏档 | 原子替换写入 + 导出备份入口（见 07） |
| Phaser 生态变动 | 模拟层零依赖 Phaser，最坏情况整体换渲染器（Pixi/Three）不动逻辑 |
