# 09 · AI 代理与自动化运行架构

## 1. 概述与设计定位

得益于项目底层的 **纯数据模拟层（`SimWorld`）与渲染层（Phaser）严格解耦** 的设计，游戏天然具备接入 AI 代理（Agent）并实现全自动运行的能力。

- **核心目标**：构建一套标准化的 AI 观察与工具调用接口（Game Tools / Function Calling），允许 LLM、强化学习模型或规则代理自主执政小镇。
- **视觉目标**：AI 在后台调用 Tools 时，前台 Phaser 画面通过动画、特效、飘字、光标移动及实时执政日志，无缝向玩家呈现“AI 实时打理小镇”的观赏性体验。

## 3. 标准游戏工具集定义 (Game Tools Specification)

按照 OpenAI / Anthropic 标准 Function Calling Schema 规范封装底层 `SimWorld` 接口：

### 3.1 规划与建设类工具
- `build_building(x: number, y: number, buildingType: string)`: 在指定坐标建造建筑。
- `demolish_building(x: number, y: number)`: 拆除建筑并按比例回收材料。
- `upgrade_building(x: number, y: number)`: 升级建筑（如 1 级民居 $\to$ 3 级民居、仓库扩建）。

### 3.2 经济与税收类工具
- `set_tax_rate(level: "very_low" | "low" | "medium" | "high" | "extortion")`: 调整人头税率，直接影响税收与幸福度。
- `fulfill_order(orderId: string)`: 提交仓库货物完成直升机/城镇订单，换取金币与经验。
- `dispatch_caravan(destination: string, payload: Record<string, number>)`: 派遣商队运货出城，换取建材或特产。

### 3.3 生产与调配类工具
- `set_production_focus(buildingId: string, recipeId: string)`: 切换工厂生产配方（如磨坊改磨精制面粉）。
- `adjust_workforce(buildingId: string, workerCount: number)`: 调配指定工坊/农田的在岗劳动力。

### 3.4 应急与民生工具
- `emergency_repair(x: number, y: number)`: 发生火灾或强盗破坏后派工抢修。
- `host_festival(costGold: number)`: 消耗资金举办节日庆典，快速拉升居民幸福度。

### 3.5 状态查询工具（只读）
- `get_town_status()`: 获取人口、幸福度、国库金币、仓储余量、季节与天气。
- `get_production_flow()`: 获取当前各级物资的每分钟产出与消耗速率报表。
- `get_pending_orders()`: 获取当前待交付订单列表与奖励详情。
- `get_disaster_alerts()`: 查询当前发生的火灾、瘟疫、强盗入侵等告警。

## 4. 实时交互与视觉呈现设计 (Visual Feedback)

为了让 AI 的后台调用转化为极具观赏性的“现场直播”，渲染层进行如下响应映射：

1. **AI 专属虚拟市长光标**
   - 画面上展示带发光特效与“AI 市长”标识的独立光标。
   - AI 发起操作前，光标平滑插值移动到目标地块/按钮，模拟真实点击轨迹。
2. **施工与操作动效**
   - 建造指令：地块出现脚手架、工人和烟雾粒子，头顶弹出扣款飘字 `"-150 💰"`。
   - 交付订单：货车/马车从仓库出发驶向出城口，弹出收益 `"+300 💰 +50 ⭐"`。
3. **AI 思考悬浮窗与实时执政日志 (CoT Stream)**
   - 侧边栏/顶部栏实时打出 AI 的思维链（Chain of Thought），增强代入感：
     > **【AI 市长 · 实时决策流】**
     > - *[08:24] 监测到当前小麦库存充足（85 单位），但面粉库存偏低（3 单位）。*
     > - *[08:25] 决定在 (12, 8) 处追加一座【磨坊】，并分配 2 名闲置劳动力。*
     > - *[08:26] 监测到冬季将至，将税率调至【低税】以维持 80% 以上幸福度。*
4. **镜头巡航与焦点跟随**
   - 玩家可开启“导播模式（Director Mode）”，相机自动平滑跟随 AI 当前重点操作的区域（如火灾扑救点、新开发区）。

## 5. 核心运行模式

### 模式 A：AI 市长全托管模式（AI Mayor）
- **玩法**：玩家纯观战。为 AI 注入不同的人设 System Prompt，观察其执政风格演进：
  - **仁慈执政官**：优先满足居民娱乐与信仰，维持超高幸福度，走慢节奏农业致富流。
  - **冷酷工业家**：极限拉满税率与重工业，压榨劳动力，高频流转订单，优先扩张领土。
  - **防御堡垒主义者**：优先铺满哨塔与消防网，囤积粮食与武器，以零损失应对一切灾害。

### 模式 B：人机协同/副官辅助模式（Co-Pilot）
- **玩法**：玩家主导大局，AI 作为执政副官。
  - **自然语言交互**：玩家输入：“帮我把北边空地规划成面包产业链”、“现在缺钱，帮我优化一下订单排产”。AI 解析后生成动作序列并执行。
  - **底层自治托管**：玩家专注于地块布局与美化，AI 在后台自动根据库存微调税率、自动扑火、自动交订单。

### 模式 C：无头极速仿真模式（Headless Benchmark & 平衡性压测）
- **用途**：在开发与调优阶段，脱离渲染引擎（零 Phaser 依赖），纯 Node.js 环境下以每秒 1000+ Tick 运行。
- **价值**：AI 代理快速跑完上百局 5 小时跨度的小镇模拟，输出经济死锁检测报告（如：是否会出现永久缺钱断粮死循环）。

## 6. 技术实现要点与工程约束

1. **异步与帧率隔离**
   - AI 的 API 请求与思考过程完全在异步 Web Worker 或外部服务中执行，严禁阻塞主线程 60fps 渲染循环。
2. **严格的规则与安全校验**
   - AI 的任何 Tool Call 都只是“操作意图”，必须经过 `SimWorld` 的硬性规则检验（检查资金、地块占用、资源前置等）。
   - 若校验失败，将结构化错误信息（如 `{"error": "INSUFFICIENT_GOLD", "required": 200, "current": 120}`）返回给 AI，由 AI 在下一轮推理中修正动作。
3. **多模型后端适配**
   - **云端 API**：兼容 OpenAI API 规范（DeepSeek-V3 / GPT-4o / Claude 3.5 Sonnet）。
   - **本地端侧模型**：通过 WebLLM 或 本地 Ollama 接口运行量化小模型（如 Qwen2.5-7B-Instruct），实现零服务器成本的单机离线运行。
