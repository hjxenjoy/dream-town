# 07 · 存档设计与本地存储方案（本项目）

## 1. 存储选型

| 方案 | 容量 | 结论 |
| :--- | :--- | :--- |
| **IndexedDB + Dexie.js** | 数百 MB | ✅ 主存档：异步、事务、索引查询 |
| localStorage | ~5-10MB | ❌ 仅存设置项（音量/画质）等小配置 |
| File System Access API | 用户磁盘 | ✅ 存档导出/导入备份功能（Chrome/Edge） |

## 2. 存档数据 schema（v1）

核心原则：**存档只存可序列化纯数据，运行时对象（渲染器/寻路/AI 状态机）启动时重建。**

```jsonc
{
  "version": 1,
  "slotId": "slot-1",
  "createdAt": 1757000000000,
  "savedAt": 1757003600000,          // 离线结算的时间锚点
  "gameTime": 864000,                // 游戏内累计毫秒
  "season": "autumn",
  "player": {
    "level": 12, "xp": 3400, "coins": 5600,
    "prestige": 28, "taxRate": 2     // 税率档位枚举
  },
  "warehouse": { "capacity": 200, "items": { "wheat": 40, "bread": 12 } },
  "buildings": [
    { "id": "b_001", "type": "fishery", "tile": [12, 8], "level": 1,
      "workers": 2, "progress": 0.6, "stock": { "fish": 5 } }
  ],
  "citizens": [
    { "id": "c_001", "homeId": "b_010", "workId": "b_001",
      "needs": { "food": 0.9, "cloth": 0.4 }, "happiness": 78 }
  ],
  "orders": [ { "id": "o_01", "items": { "bread": 3 }, "rewardCoins": 60, "rewardXp": 15 } ],
  "caravans": [
    { "id": "cv_1", "type": "land", "state": "outbound",
      "cargo": { "cloth": 2 }, "returnAt": 1757005400000 }
  ],
  "research": ["smelting", "crop_rotation"],
  "achievements": { "pop_50": true },
  "stats": { "totalCoinsEarned": 40000, "disastersSurvived": 2 }
}
```

## 3. 启动加载流程

```
读取存档 → 版本检查(必要时逐级迁移) → 重建世界状态
  → 离线结算(见 06 文档, 以 savedAt 与当前时间差为 t)
  → 弹出离线收益报告 → 进入游戏
```

## 4. 版本迁移

- 每次数据结构变更 `version + 1`，注册迁移函数 `migrations[v] = (save) => save'`；
- 启动时从存档 version 逐级执行到最新，**禁止跨级跳转**；
- 迁移失败则保留原存档并提供"导出备份 + 开新档"选项，**绝不静默毁档**。

## 5. 存档时机与多槽位

- **自动存档**：每 30 秒（脏检查）+ `visibilitychange` 切后台 + `beforeunload`；
- **手动存档**：3 个槽位 + 1 个自动槽轮转；
- 写库用 Dexie 事务，先写临时 key 再原子替换正式 key，防止中途断电/刷新产生半截存档；
- 导出/导入：JSON 序列化 + 时间戳命名文件（File System Access API，降级为 `<a download>`）。

## 6. 防作弊与完整性（弱需求，单机）

- 存档加简单校验和（CRC32）检测手改损坏；
- 不做强加密——单机游戏允许玩家改档，是离线游戏文化的一部分。
