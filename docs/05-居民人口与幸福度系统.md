# 05 · 居民、人口与幸福度系统（本项目）

## 2.8 补充

园艺每升一级，自然增加 2 位社区人口名额（园艺最高 30 级，共可增加 58 位）。与学校、诊所、剧院及已有称号名额叠加，入住仍受健康住宅床位、幸福度与口粮限制。无需任务交付或领取。

## 1. 人口模型

```
建房/升级民居 → 空床位 → 移民入住(条件: 幸福度 ≥ 阈值 且 粮食库存 ≥ 3 日)
居民 = 生产者(上班) + 消费者(需求) + 纳税人(人头税)
```

- **人口决定用地规模**（学 Township）：人口越多，可开垦的农田/区域越多。
- 人口上限由**社区建筑**（学校/诊所/剧院）提升——建材可来自商队运输，或采矿研究后由窑火建材坊本地制造（6 石料 + 1 木炭 → 1 建材）。社区名额与住宅床位共同限制可入住人口。
- 移民流入速率与幸福指数正相关；幸福度崩坏则居民搬离（负增长）。

## 2. 需求分层（马斯洛式递进）

下表是最初的分层设想。**当前实现状态见「本层实现」列**，落点细节见 2.9。

| 层级 | 需求 | 满足建筑/物资 | 不满足后果 | 本层实现 |
| :--- | :--- | :--- | :--- | :--- |
| L1 生存 | 食物、饮水 | 鱼/面包/肉；水井 | 幸福度急跌，停止纳税，搬离 | 已实现（食物按三日口粮折算，饮水按住宅覆盖） |
| L2 温饱 | 衣物、燃料(冬) | 裁缝铺衣物；木板/木炭 | 幸福度缓降，效率下降 | **已实现，但改为加成**：衣物每日消耗，备足 +最多 4 点幸福度，缺货不罚；冬季燃料已实现（扣木材） |
| L3 小康 | 娱乐、酒馆 | 酒馆(啤酒/香肠)、娱乐场 | 无法升高档税率 | **部分实现**：蜂蜜/奶酪/葡萄酒/陈年佳酿每日消耗并给 +最多 4 点；酒馆与娱乐场这两座建筑仍未做 |
| L4 富足 | 信仰、医疗 | 教堂、医馆 | 瘟疫易爆发；顶层税率锁死 | **已实现，改为减负**：教堂新增（信仰），诊所获得真正的康健职能；两项都按「服务居民数 ÷ 人口」折算，只减轻重税惩罚与修缮费，缺了不罚（见 2.10） |

> 与实际不符的"不满足后果"一列保留为原始意图，实施时统一取**只加不减**的方向（见 2.9 的理由）。

## 2.9 温饱与闲适：成品的居民侧出口

《04》把衣物、奶酪、葡萄酒写进了居民消费链，但一段时期里这些成品只有"卖钱"一条出路。2.9 补上居民侧出口，落点刻意做成**加成而非惩罚**。

### 需求表（现行）

| 需求 | 满足来源 | 折算 |
| --- | --- | --- |
| 食物 | 鲜鱼 + 面包 | 三日口粮 |
| 饮水 | 水井 / 供水塔覆盖的住宅 | 覆盖床位占比 |
| 社区生活 | 市政设施的服务值 | 直接取和，含 10 基础值 |
| 环境 | 建筑环境值 + 街区风格 + 邻居故事加成 | 60 基础值起算 |
| **温饱** | **衣物** | 三日储备 |
| **闲适** | **蜂蜜 / 奶酪 / 葡萄酒 / 陈年佳酿** | 三日储备 |

### 消耗规则

- 每 **8 位居民每天 1 件衣物**，每 **10 位居民每天 1 份闲适**，均向上取整（`Math.ceil`），因此 1 位居民也照常消耗一份。
- 闲适按**由廉到贵**取用：蜂蜜 → 奶酪 → 葡萄酒 → 陈年佳酿。贵的酒只有在更便宜的都用尽时才会被开瓶，于是陈年佳酿实际是留给贸易的。
- 在线在每日结算（`settleDay`）扣减；离线按经过的天数乘算，并逐项计入 `report.consumed`，因此离线报告仍满足「起始 + 产出 − 消耗 = 结束」的守恒断言。
- 库存不足时**只扣到 0**，视为"没能提供"，不产生额外惩罚。

### 幸福度

```
目标幸福度 = 食物×0.4 + 饮水×0.25 + 社区×0.2 + 环境×0.15
            + (温饱 + 闲适)/200 × 8
            − 税率惩罚 − 灾害惩罚 + 庆典/活动加成
```

四个权重 0.4 / 0.25 / 0.2 / 0.15 与它们对应的四项基础需求完全沿用本文第 3 节的初版模型，**没有改动**。新增的只有末尾那个上限 8 点的加项（2.10 的信仰与康健另行减轻税率惩罚，不改动基础项）。

这个"只加不减"的选择是有意的：本作定位是无失败状态的轻松经营（《01》《12》），因此新链不该变成新的生存门槛。缺衣物的小镇与 2.9 之前完全一致——这一点有测试直接断言（裸镇恰好等于四项基础值），也因此《15》的既有配平不被推翻：任何在 2.9 之前健康的存档，加入本层后只会更高兴或持平。

### 存档

`needs` 新增 `comfort` / `leisure` 两个**可选**字段：旧档缺这两个键仍能读取，构造函数补 0，下一次 `updateNeeds()` 即按实际库存重算。校验对越界值（负数、小数、>100）依旧拒绝。

## 2.10 信仰与康健：把重税与灾害变得可承担

L4「富足」层在很长一段时间里是空的：没有教堂，而诊所只有人口名额与服务值两项数据，与「医疗」这个名分无关。2.10 把它补上，落点与 2.9 一致——**只减轻代价，不制造惩罚**。

### 两个新读数

| 读数 | 来源 | 折算 |
| --- | --- | --- |
| **信仰** | 河畔小教堂（每级 14 户） | 服务户数 ÷ 人口 → 0–100 |
| **康健** | 安心诊所（每级 10 位） | 服务人数 ÷ 人口 → 0–100 |

两者都是**「服务了多少人」对「镇上住了多少人」**，与供水率的算法同构。受损的建筑不提供服务（与住宅、水井、消防的既有口径一致）。

教堂不挂任何科技：它是基础市政，走哪条路线的玩家都拿得到，价格 1500 金币 / 每级 8 点社区名额。

### 两项实际作用

| 读数 | 作用 | 上限 |
| --- | --- | --- |
| 信仰 + 康健 | **减轻税率幸福惩罚**：`penalty × (1 − 0.4 × (health + faith)/100)` | 最多减 80% |
| 康健 | **减轻修缮费**：只减人工部分，`ceil(coins × (1 − 0.3 × health/100))` | 最多减 30% |

两处都设了上限，因为**顶档 20% 税率的代价本身就是设计的一部分**（《05》第 4 节要的是「提税增收 vs 保幸福」这个决策）。让服务把惩罚清零，等于把这个决策删掉；减到八成是「好好经营能撑住重税」，而不是「重税没有代价」。

修缮折扣**只作用在人工费**上，现买材料（《15》那套木材 45、石料 55 的应急价）一分不减——否则修好诊所就同时削弱了那条安全阀。

### 为什么仍然只加不减

和 2.9 同样的理由：缺教堂、缺诊所的小镇，幸福度与修缮费**与没有这一层时逐位相同**（有测试直接断言：无服务的小镇恰好付满额税率惩罚）。所以这一层不是新的生存门槛，而是给「把小镇照顾得更好」这件事一个具体回报。

它还顺手给顶档税率补上了原本缺失的支撑：2.10 之前，重税只降幸福度、没有任何经营手段可以缓解，导致 20% 档在实践中是一条死路；现在它是一条需要配套的路。

## 3. 幸福度计算模型

```
幸福指数(0~100) = Σ(需求满足率 × 权重) − 税率惩罚 − 灾害惩罚 + 节庆加成

权重(初版): 食物 30 / 饮水 15 / 衣物 15 / 娱乐 15 / 信仰 10 / 医疗 10 / 环境 5
税率惩罚: 税率每 +1 档，幸福 −6
灾害惩罚: 火灾受损 −10(逐日恢复) / 瘟疫期间 −20 / 被抢 −8
```

## 4. 税收档位（核心决策点）

| 档位 | 税率 | 效果 |
| :--- | :--- | :--- |
| 免税 | 0% | 幸福 +5/日，移民加速 |
| 低 | 5% | 无惩罚 |
| 中 | 10% | 幸福 −6 |
| 高 | 15% | 幸福 −12，需 L3 需求满足才可长期维持 |
| 重 | 20% | 幸福 −20，仅短期应急（灾后重建募资） |

**设计张力**：玩家每季度做一次"提税增收 vs 保幸福保人口"的权衡——这是 Townsmen 最经典的经营决策。

## 5. 居民个体表现（氛围层，低成本高回报）

Townsmen 被社区盛赞的"精度用在刀刃上"设计，本项目以 2D 精灵低成本复刻：

- 居民有住所→工作地两点通勤动画（A* 寻路）；
- 建筑专属音效：市场喧闹、铁匠铺敲打、磨坊吱呀、酒馆歌声；
- 状态外化：幸福时闲聊/节庆跳舞，不满时聚集抱怨，重税时罢工（生产停摆）；
- 灾害时强盗进村与守卫决斗的小剧场。

## 6. 声望与科技

- 完成任务链（NPC 委托/里程碑）获得**声望**；
- 声望解锁：新建筑蓝图、科技升级（生产 -10% 时间、仓库 +20%、税率惩罚减半等）、剧情章节；
- 单机替代 Township 赛季通行证的长期目标系统：**成就树**（人口 100 / 全建筑解锁 / 无伤抗过瘟疫……）。
