# 作物成长表现

> 2026-09-22 更新：原先的「一张生长图 + 一张成熟图 + 着色」两态表现，已被四阶段素材取代。
> 下面先写当前实现，2026-09-12 那一轮的记录保留在文末，作为历史。

## 当前实现（2026-09-22）

一块田现在有四张自己的画面，按进度逐级换帧，**田地尺寸全程不变，只有植株长高**。

| 进度 | 阶段 | 画面 |
| --- | --- | --- |
| 0–22% | `sprouting` | `-sprout`：破土幼苗 |
| 22–72% | `growing` | `-young`：枝叶初展 |
| 72%–未成熟 | `ripening` | `-growing`：接近成株 |
| `ready` 为真 | `ready` | `-ripe`：完整植株，可收获 |
| 休耕 | `fallow` | 不画作物，只剩空田 `farm0` |

- `ready` 始终是唯一权威：进度条满但尚未结算时不显示成熟画面。
- 不再用绿色着色表示「未熟」，四张画面本身就表达生长程度。
- 田园面板的「正在萌芽 / 枝叶渐丰 / 快成熟了」文案沿用同一套阶段判定（`cropGrowthStage`）。

## 素材与三张图集

四阶段帧来自 `public/assets/readiness-2026-09/` 的三张图集，每种作物四帧：

| 图集 | 作物 | 地块宽度（帧内像素） |
| --- | --- | --- |
| `crop-stages-1` | 小麦、胡萝卜、玉米 | 272 |
| `crop-stages-2` | 番茄、草莓、南瓜 | 247 |
| `crop-stages-3` | 向日葵、葡萄、苹果 | 271 / 265 / 267 |

**三张图集的取景比例不同**，所以渲染时不是按帧宽缩放，而是按**各自的地块宽度**缩放：
`scale = 104 / soilWidth`，104 是游戏里一块田的屏幕地块宽度（与 `farm0` 一致）。
少了这一步，番茄田的地块会比旁边的小麦田小 9%。地块宽度实测自每张图集的
`sprout` 帧——那时土块是画面里最宽的东西。

落点用素材自带的 `origin`（约 `0.5, 0.978`，即土块近角），并把精灵下移 21px，
使近角落在格子中心，与休耕时的 `farm0` 完全重合：**播种或收获时田地不会跳动或改变大小**。

## 验证

- 366 项测试通过（含本轮的作物四阶段契约测试、渲染尺寸规则）。
- `crop-growth.test.ts` 从左到右扫过进度值，断言九种作物各自依次经过
  `sprout → young → growing → ripe`，不跳帧不重复，且休耕不返回任何作物帧。
- 生产构建与离线检查通过，预缓存 63 项 / 24.46 MB。
- 真实页面：在农业区把六块田分别设为小麦 / 番茄 / 向日葵 / 胡萝卜 / 草莓 / 葡萄（约 40% 进度），
  同屏可见六种不同植株与大小一致的地块；4 倍速下按进度继续换帧，控制台无 error。

## 历史：2026-09-12 两态版本

那一轮补齐的是九种作物的中期生长画面，不新增照料动作、任务或经济消耗。

- 进度低于 22%：萌芽。苹果树和葡萄保留无果的树体与支架。
- 22% 到 72%：使用各自的绿色生长图；番茄、草莓和南瓜可见花朵。
- 72% 后：进入成熟前画面。只有模拟层 `ready` 为真才显示可收获。
- 休耕：回到空田；恢复种植后重新按进度显示。

素材用内建 ImageGen，以当时的 `public/assets/crops.png` 为风格参考生成，未替换成熟素材。
原图 `output/crop-growth-2026-09-12/crops-growing.png`，图集 `public/assets/crops-growing.webp`，
帧目录 `public/assets/crops-growing-frames.json`，实际尺寸 1254 × 1254、RGBA、九帧、
约 50.2% 完全透明像素，九帧边界均无 alpha > 32 的像素。

**该图集已于 2026-09-22 退出运行**：`src/sim/atlases.ts` 不再登记它，`TownScene` 不再加载它，
`vite.config.ts` 把它移出预缓存（约 1.05 MB），`verify-offline.mjs` 断言它「必须未缓存且无人引用」。
文件保留在仓库里供比对，但不再随游戏下载。
